    Localisation key reference¶

    Every player-facing string in the template is addressed by a dotted key and resolved through the Lexicon static class from a JSON table in Assets/ChosenOfTheHarvest/Resources/Localization. This page documents the key convention, lists all 349 English keys grouped by prefix, and explains the ?XX?-prefixed pseudo-locale used for layout testing.

    How Lexicon resolves a string¶

    Member Returns Description
    Locale string Active locale id, "en" until SetLocale
    Get(string key, string fallback = null) string Table value, else fallback, else the key itself
    Format(string key, string fallback, params object[] args) string Get then string.Format; a broken template returns unformatted text
    KeyCount int Entries loaded for the active locale
    SetLocale(string next) void Switches locale, clears the cache, reloads on next lookup

    The table is Resources/Localization/<locale>.json, loaded once and cached until the locale changes. A missing file leaves the table empty rather than throwing, so every string falls back to its in-code default. The file shape is fixed by JsonUtility:

    {
  "entries": [
    { "key": "title.name", "value": "CHOSEN OF THE HARVEST" }
  ]
}

    Lexicon.Get is also used with a literal default at the call site, which is why code reads like Lexicon.Get("dungeon.locked", "The door is locked …") — that second argument is the fallback, not a translation.

    Duplicate keys: last one wins

    menu.assign.title is defined twice in en.json — once as ASSIGN and later as ASSIGN {0}. The loader assigns Values[key] = value in file order, so the later entry replaces the earlier one. Remove the first entry when you translate.

    Where the locale is chosen

    Preferences.Language is stored in PlayerPrefs as choth_settings_language. Settings page 2 cycles English ⇄ Pseudo, and HarvestGame applies it through Lexicon.SetLocale when the game starts.

    Key naming convention¶

    Rule Example
    <system>.<subject>[.<detail>], lowercase, dot separated quest.hymn, trait.lazy.desc
    Compound subjects are concatenated, never hyphenated dungeon.treasuretaken, menu.actions.reflection
    Screen and menu titles are ALL CAPS campaign.title, shop.sell.title
    Toast keys mirror the action that produced them companion.blessed, slots.deleted
    Input prompts are prefixed with the key glyph [E] Descend deeper, [B] Build
    Fields are separated by a spaced bullet • ACT I • ASHEN ORCHARD • The Gilded Stag
    Placeholders are positional {0}–{3}, filled by Lexicon.Format shop.heirloom = {0} • 25 pearls • stock {1}
    Ellipses are three ASCII dots, never … The rose garden is growing...

    Four prefixes are composed at runtime from an enum name, so the key is never a literal in code:

    Composed key Source Values
    building.<type> Sanctum.Label, type.ToString().ToLowerInvariant() 20 building names
    room.<type> FloorPlanGenerator.Name(type) entrance … forge
    trait.<trait> / trait.<trait>.desc CompanionCatalog 6 traits × 2
    phase.<phase> SeasonCycle.PhaseName dawn, day, dusk, night

    campaign.act1–campaign.act3 sit in a fixed array, and quest.* / npc.hint.* are referenced from ordered lists in QuestSystem and HarvestGame, so their key names are positional: reordering those lists reorders the story.

    The pseudo-locale¶

    xx.json is a layout test, not a translation: it has the same 349 keys in the same order, and every value is the English text prefixed with the literal ASCII marker ?XX?.

    {
  "entries": [
    { "key": "title.name", "value": "?XX? CHOSEN OF THE HARVEST" },
    { "key": "dungeon.runes", "value": "?XX? Runes {0}/{1}" }
  ]
}

    Because the marker is plain ASCII it renders in any font, so a missing glyph shows up immediately, and {0} placeholders survive so Format calls still exercise their arguments. Two ways to use it:

    • In the build: Preferences → page 2 → Language switches English ⇄ Pseudo (layout) at runtime.
    • In the smoke test: SmokeTest switches to xx, formats hud.day, and logs SMOKE locale pseudo=… keys=349 before switching back — the fastest way to catch a table that failed to load.

    Add a real locale

    1. Copy en.json to <code>.json (for example de.json) in Resources/Localization.
    2. Keep every key string byte-identical and keep the {0}–{3} placeholders in the translated values.
    3. Keep layout-bearing spacing in hud.* and the • separators.
    4. Switch with Lexicon.SetLocale("de"), then confirm Lexicon.KeyCount matches 349.
    5. If the table fails to parse, Lexicon logs Lexicon table failed to load: … and falls back to code defaults.
